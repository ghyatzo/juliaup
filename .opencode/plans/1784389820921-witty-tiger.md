## Context
PR1 (`centralize-paths-v2` bookmark, `086e00db`) is implemented and passing tests. Three revisions are needed based on review:

## Revision 1 — Fix the incorrect `.exe` comment in `global_paths.rs`

**Problem:** The comment I added explains the `parent().join("juliaup")` pattern as a Windows `.exe` suffix workaround. That's false — `current_exe()` on Windows returns the `.exe` suffix (via `GetModuleFileNameW`), and `dunce::canonicalize` preserves it.

**Real reason:** `get_paths()` is called from both `julialauncher.rs` and `juliaup.rs`. When the **launcher** (`julia`/`julialauncher`) calls it, `current_exe()` returns the launcher's path, not `juliaup`'s. The launcher and `juliaup` are **siblings** in the bin dir, so we go `parent()` → bin dir, then `.join("juliaup")` → the juliaup binary.

**Fix:** Replace the comment at `src/global_paths.rs:73-78` with the correct explanation.

**Problem:** Removing `JULIAUP_BIN_DIR` made the conflation of "where symlinks go" vs "where the binary is" *worse*. `JULIAUP_BIN_DIR` is actually the mechanism that lets users control symlink placement independently of the binary location — it's the right tool for the concept split we identified. It should stay (non-breaking).

**Fix in `src/utils.rs`:** Revert to the original `get_bin_dir` structure with the `JULIAUP_BIN_DIR` env var branch, but change only the fallback source from `current_exe().parent()` to `paths.juliaupselfexecfolder`:

```rust
pub fn get_bin_dir(paths: &GlobalPaths) -> Result<PathBuf> {
    let entry_sep = if std::env::consts::OS == "windows" { ';' } else { ':' };
    let path = match std::env::var("JULIAUP_BIN_DIR") {
        Ok(val) => {
            let path = PathBuf::from(val.split(entry_sep).next().unwrap());
            if !path.is_absolute() {
                bail!("The `JULIAUP_BIN_DIR` environment variable contains a value that resolves to an an invalid path `{}`.", path.display());
            };
            path
        }
        Err(_) => {
            let mut path = paths.juliaupselfexecfolder.clone();
            if let Some(home_dir) = dirs::home_dir() {
                if !path.starts_with(&home_dir) {
                    path = home_dir.join(".local").join("bin");
                    if !path.is_absolute() {
                        bail!("The system returned an invalid home directory path `{}`.", path.display());
                    };
                }
            }
            path
        }
    };
    Ok(path)
}
```

Re-add `anyhow` to the `use anyhow::{anyhow, bail, Context, Result};` import if needed (check: `anyhow!` macro may not be used — the `bail!` calls don't need it. But the original had it, so check during implementation).

## Research: how other version managers handle self-location (for PR2 RFC context)

| Tool | Discovery authority | Self-update mechanism |
|------|---------------------|----------------------|
| **rustup** | `CARGO_HOME` env var — single root for binary + proxies + config. No `current_exe().parent().parent()`. Proxies (`cargo`, `rustc`) are hardlinks to `rustup` in `CARGO_HOME/bin`. | download `rustup-init` into `CARGO_HOME/bin`, run `--self-replace` which copies itself into place + re-creates hardlinks |
| **uv** | **install receipt** (`uv-receipt.json`) written next to the binary at install time. `self update` loads the receipt, *validates* `current_exe()` matches the receipt's prefix, then delegates to `axoupdater` or re-runs the installer. No receipt → "installed via package manager." | `axoupdater` (separate updater binary) or re-run installer script |
| **mise / asdf** | package manager (no self-update) | defer to `brew upgrade` etc. |
| **juliaup (current)** | `current_exe().parent().parent()` — re-derived at runtime | download tarball, extract over bin dir, spawn `_post-update` |

**juliaup is the outlier**: it re-derives its install root from `current_exe()` at runtime instead of either (a) using an env var as the authority (rustup's `CARGO_HOME`) or (b) writing down where it was installed (uv's receipt). The PR2/RFC proposal (make `JULIAUP_DEPOT_PATH` the sole authority) would move juliaup from "re-derive at runtime" to "env var authority" — matching rustup's proven model and eliminating the parent-of-parent fragility.

**Implication for PR2**: the uv-style "install receipt" is an alternative to the env-var-authority approach worth considering in the RFC. A receipt would let juliaup keep its current `~/.juliaup` vs `~/.julia/juliaup` split (recording both paths at install time) while still eliminating the runtime `current_exe()` derivation. But the env-var approach (rustup-style) is simpler and already half-implemented via `JULIAUP_DEPOT_PATH`.

## Research: why julialauncher spawns juliaup

`julialauncher` and `juliaup` are **two separate binaries** with a deliberate division of labor:
- **launcher** (`julialauncher.rs`, shipped as both `julia` and `julialauncher`): the fast path — figure out which Julia to run and exec/spawn it. Must stay cheap, never block on config writes or network.
- **juliaup**: the management CLI — downloads versions, updates version DB, self-updates, initial setup, modifies PATH.

The launcher spawns juliaup (via `paths.juliaupselfexec`) for four tasks, all in the double-forked daemon child (Unix) or post-spawn section (Windows):
1. **`do_initial_setup`** (`julialauncher.rs:40`) — first-run bootstrap: `juliaup 46029ef5-…` (`InitialSetupFromLauncher`, `cli.rs:61`)
2. **`run_versiondb_update`** (`julialauncher.rs:50`) — throttled background: `juliaup 0cf1528f-…` (`UpdateVersionDb`, `cli.rs:63`), detached + stdio-null
3. **`run_selfupdate`** (`julialauncher.rs:83`) — throttled background: `juliaup self update`, detached
4. **`spawn_juliaup_add`** (`julialauncher.rs:236`) — interactive auto-install: `juliaup add {channel}`, waited on

The split exists so the launcher can **exec Julia and let juliaup's background work continue independently** — Julia doesn't wait for version DB updates or self-updates. This is also why `get_paths()` must work from *either* binary, and why the `parent().join("juliaup")` pattern exists: when the *launcher* calls `get_paths()`, `current_exe()` returns the launcher's path, and juliaup is its sibling in the bin dir.
